# 架构与接口

## 控制层次

- 规则任务管理器：approach → pregrasp → insert → grasp → press → push → release → retract → traverse。
- 目标生成：对齐把手、绕把手轴圆弧下压、跟随门铰链圆弧推门。
- 6D阻尼最小二乘IK：末端位置和姿态 → 六轴关节目标；有关节范围、每步目标变化约束。
- 仿真执行：机械臂PD＋模型偏置补偿；独立夹爪；底盘速度 → 冻结的12维腿策略 → 腿PD。
- 残差PPO：10维动作（底盘3、TCP位置3、姿态3、夹爪1），**阶段切换仍是规则，不是已训练HRL管理器**。

## 物理抓握

两指碰撞体必须真实接触把手，法向力各大于0.15 N、相对速度小于0.07 m/s、闭爪目标有效，连续保持0.25 s。没有weld、吸附或写门角度的“抓取捷径”。这些阈值只定义仿真实验，不是硬件控制参数。

门轴阻尼、摩擦阻力和回位弹簧为0；把手弹簧保留。门有惯性和开角限位，因此推开后可能继续转动或因限位碰撞反弹；这不等于自动关门器。

门锁是简化的关节约束：稳定抓握且实际把手压到阈值后解除。它不是完整锁舌碰撞模型，必须承认这一简化。

## 视觉与坐标

相机RGB＋已知camera-ID → 分割预测；深度与相机变换 → 可见表面点云。点云中心不是规范抓取点，也不能直接把两视角中心平均当成同一个点。

`DualCameraObserver.features()`输出12维：每视角TCP坐标下可见表面偏移3、置信度、面积比例、有效性。当前供观察/记录，**没有接入控制策略**。

`T_world_camera = T_world_base × T_base_wrist(q) × T_wrist_camera_optical`。仿真中变换精确已知；现实中必须用测量和标定，且处理时间同步。

## 真机接口

`deployment.safety`只验证命令，不连接硬件。`DryRunBackend`只能记录机械臂目标，夹爪和底盘方法明确拒绝执行。完整自主开门transport尚未实现。

`hardware/arm`是独立保留的原ROS执行层；不能把仿真关节数组和夹爪力映射假定为它已支持的接口。
