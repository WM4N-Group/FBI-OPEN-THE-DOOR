## 独立初始姿态对照

先按课程验证平均耗时选择seed44，再用未参与训练/门禁的990000～990031共32个初始姿态进行配对测试。没有根据这批测试重新挑选模型或调整参数。

| 控制器 | 完整流程成功 | 各自成功回合平均耗时 | 成功耗时范围 |
|---|---:|---:|---:|
| 规则＋IK＋相同冻结腿策略（零高层残差） | 28/32 | 20.67 s | 20.4～21.4 s |
| 上述基线＋确定性PPO高层残差 | 32/32 | 16.34 s | 16.2～16.6 s |

4次基线失败均为压把手阶段超时。按各自成功回合计算约快21%；仅比较两者共同成功的28对，均值为20.67 s对16.32 s。应区分成功条件均值与全体回合耗时，不能把超时失败的耗时直接用于“速度提升”。

**范围非常有限**：仍是同一门/把手资产、相同物理参数、小范围初始机身位置和朝向；两者均使用仿真真值把手位姿/轴线。它证明该测试下残差策略有收益，不证明其他门型、真实视觉、延迟/摩擦扰动或真机可靠性。32/32也不是普遍100%成功率保证。

## 受力诊断

诊断只采样10Hz，不是高频峰值力验收。每回合最大值再取均值：

| 统计口径 | 臂部最大指令力矩：基线 / RL | 较大指端接触力：基线 / RL |
|---|---:|---:|
| 各自全部32回合（基线含4次失败） | 17.45 / 20.04 Nm | 8.73 / 9.37 N |
| 共同成功的28对回合 | 18.82 / 20.04 Nm | 9.34 / 9.37 N |

不能把包含失败样本的不同分布统计直接当成接触安全结论。较快候选仍需限力、滑移、高频接触和整机稳定性验证。10Hz诊断未发现>5N的非预期外部接触事件，也不等于所有时刻都无碰撞。

## 复现命令

先完成私有reference导入和`sim-build`，再在仿真环境中：

```bash
fbi-door evaluate-paired \
  --checkpoint /absolute/path/to/trusted/final_seed44.zip \
  --expected-sha256 6a9459cace463f8469e6a376f6d2fdecaf61e7d7334ede31e6d0c8c00a844059 \
  --policy-seed 44 --seed-start 990000 --episodes 32 \
  --output-name paired_seed44_fresh_32 --record
```

- 结果写入`FBI_DOOR_RUNTIME/reports/<output-name>`，拒绝覆盖已有目录。
- `--record`只录候选的第一个回合，10fps、1倍仿真时间、完整回合；需要ffmpeg。视频明确显示特权几何和残差＋规则/IK，不冒充视觉控制。
- 仅加载受信任checkpoint；ZIP CRC/SHA校验不使任意pickle变得可信。
- 默认使用CPU策略推理，不发送任何真实硬件指令。
- 新CLI不会声称调用者给定的种子必然没用过，调用者必须维护种子划分。
