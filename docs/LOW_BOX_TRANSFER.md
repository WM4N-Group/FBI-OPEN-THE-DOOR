# 低箱无需重训测试：几何适配，不是原样零样本成功

2026-11-14，独立仿真评估；没有进行任何梯度更新，也没有更改默认`clearance_v2`训练控制器。

## 结论

**20 cm与30 cm高的箱子，在本次几何适配后可以完成推箱、退离和收臂，不需要重新训练权重。** 但原策略＋原控制器完全不改时，这两种低箱都未通过；不能将其描述为“原样泛化成功”。

相同8个新初态（920100～920107），相同40×50 cm底面、2 kg质量、滑动摩擦0.35、平地。初始箱体轴与世界轴对齐并沿+X推动；初态扰动只含机身小幅位置/偏航和箱体平移，不含箱体初始旋转：

| 箱高 | 原PPO＋原控制器不改 | 原PPO权重＋几何适配 | 几何＋IK、零高层残差 |
|---|---:|---:|---:|
| 30 cm | 0/8 | **8/8** | **8/8** |
| 20 cm | 0/8 | **8/8** | **8/8** |
| 15 cm | 0/8 | **0/8，地面间隙保护** | **0/8，地面间隙保护** |

“零高层残差”仍复用原冻结的12维腿RL策略，不是机器人完全不用既有学习策略。成功要求完整任务和原v2验收通过，并额外要求指垫正面接触时间≥0.4 s、正面法向冲量占比≥90%，避免把压箱顶当成正面推箱。

## 做了哪些非学习改动

原控制器接触TCP高度固定0.34 m。仅降低该高度的开发测试也不够：手臂受推力后靠近机身，触发自碰间隙保护；这不是通过关闭碰撞来解决的。

本次通过的**固定几何方案**：

- 接触TCP高度取`min(0.34, box_height - 0.02)`，因此20 cm箱对应0.18 m目标（不含原有有界残差）。
- 底座参考点至箱前平面的接近停距目标由0.63 m改为0.70 m，提前请求原有减速/停稳阶段；这不是机身外壳到箱子的实际间隙。
- 工具轴向下倾角由30°改为45°，重新做完整位姿IK和原有路径检查。
- 原末端横向夹爪姿态、指垫几何、IK/PD、关节限位、速度/力矩限制、25 mm规划自碰间隙、实际间隙/受力停止规则、退离与收臂要求均保留。
- 不修改机器人资产，只改变箱体高度和reset中心高度；质量/摩擦/底面尺寸不变，箱体仍为自由刚体。几何变化自然改变其惯量，但没有额外任务执行器、焊接或rollout位姿写入。

几何参数先在开发种子920000上选择，再固定用于920100～920107回归；没有用回归结果继续调参。它是**无需重训的模型控制适配**，不是零调参的RL泛化或普遍成功率证明。

## 实测边界

20 cm组：

- 原PPO＋几何适配：箱体前移0.555～0.569 m，平均40.64 s。
- 零高层残差＋几何/IK：前移0.539～0.545 m，平均42.47 s。
- 检查的自碰代理最小间隙约30.1 mm，机械臂—地面最小间隙至少95.1 mm；监测自接触和非指垫臂段撞箱峰值均0。
- 两种成功方案的指垫接触法向冲量均来自箱子正面，没有靠压箱顶完成任务。

15 cm组：按相同几何方案接触后，手臂下方间隙降到约49 mm，触发原50 mm停止线，未完成任务。**这是安全余量不足的停止，不等于已经碰地，也不证明所有15 cm方案都不可能。** 没有放宽地面/自碰保护来换取通过。

原PPO＋原控制器不改的三种低箱，均因接触点偏高、继续靠近时触发底座—箱体间隙保护而失败。40 cm数值等价场景的开发对照成功，证明不是场景复制破坏了原任务。

权重来自完成训练的seed200（按编号选作参考，不宣称最优）。每次运行均校验输入checkpoint SHA256；比较推理前后完整高层策略张量指纹及训练步数，确认不变。原冻结腿checkpoint同样校验。仍使用仿真真值几何，没有训练箱高视觉识别。

## “能推低箱”不等于“能作为台阶上高台”

本次保持2 kg轻箱，只验证push。没有测试踩踏、攀登、载荷、箱体被踩时的滑移/倾覆或真实结构强度，也没有证明原腿策略具备上台阶能力。

面向后续导航任务，应将操作的交接条件升级为：箱体在指定位置/朝向、稳定、具有可用落脚区域、满足下一攀登技能的启动条件，而不只是前移超过0.5 m。推箱时禁止腿撞箱；踩踏时则需要独立的允许接触集合和攀登控制器，不能直接沿用当前push验收。

## 复现

在新的独立runtime复制授权场景，保留原运行目录不动：

```python
from fbi_door.box_height import build_height_variant
build_height_variant(
    "/absolute/path/to/original-box-runtime",
    "/absolute/path/to/new-height20-runtime",
    .20,
)
```

```bash
export FBI_DOOR_RUNTIME=/absolute/path/to/new-height20-runtime
export MUJOCO_GL=egl OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
python -m fbi_door.sim.evaluate_box_height \
  --checkpoint /absolute/path/to/trusted-seed200-policy_latest.zip \
  --expected-checkpoint-sha256 6f9240c2dff10d2b61ad4a767c58c53aca2e29b865acc12eb6d2a8a9c55144eb \
  --modes strict_ppo pose_ppo pose_ik --count 8 --seed 920100 \
  --output "$FBI_DOOR_RUNTIME/reports/height20.json"
```

`height_ppo/height_ik`是只改低IK点、仍保持原停距/倾角的开发消融；`pose_ppo/pose_ik`额外使用上述停距和倾角。视频模式只能指定一个控制器，记录首个回合。场景/结果拒绝覆盖旧文件。原始结果见`provenance/box_height_20261114/`；这些接口为显式评估工具，未替换默认控制器或实现共享世界长程导航后端。
